#SeverityWhat happensEvidence
F1highSessions end 10 minutes after login, even mid-use, with no warning

The session cookie is set once at login with a fixed 10-minute expiry, and nothing extends it while you shop. The next page change throws you to the login screen with 'You can only access /cart.html when you are logged in', which reads like you did something wrong.

When: Ten minutes after logging in, active or not

Fix: Extend the session on activity, warn before it ends, and word the message as 'Your session timed out'.

graph check · happens often · ghost state · Session ends 10 minutes after login

  • utils/Credentials.js:27-32 Fixed expiry: now + 10 minutes, set only at login
  • components/PrivateRoute.jsx:13-17 Checked on every page change
  • pages/Login.jsx:22-28 Message shown after the redirect
F2highA mistyped or old URL shows a blank page with no way out

There is no 404 route. When nothing matches, React Router renders nothing: no header, no menu, no link home. The only way out is editing the address bar.

When: Any URL that matches no route, when the host serves the app for it

Fix: Add a catch-all route that shows a 'page not found' message with a link to the product list.

graph check · edge case · dead end, silent failure · Blank white page

  • index.jsx:36-86 No path="*" route
  • react-router-dom 7 (package.json ^7.18.3) <Routes> renders nothing when no route matches
F3highYou can add an item that doesn't exist, and then you can't remove it

The not-found page still offers Add to cart. It saves the bad id, the button flips to Remove, and the cart badge counts it. The cart page has no row for it, so it can't be removed there. The badge stays wrong until someone finds Reset App State in the menu.

When: Add to cart on the 'ITEM NOT FOUND' page (a bad link, or problem_user opening the last product)

Fix: Hide Add to cart when the item isn't found, and drop unknown ids when reading the cart.

graph check · edge case · ghost state, silent failure · Item that doesn't exist saved to cart

  • pages/InventoryItem.jsx:83-84 Saves whatever id the page has
  • utils/shopping-cart.js:2-14 No check that the id is a real product
  • components/CartButton.jsx:24-27 Badge counts every saved id
  • pages/Cart.jsx:40-42 Looks up each id; unknown ids are undefined
  • components/CartItem.jsx:18-20 Undefined item renders an empty div, with no Remove button
  • pages/InventoryItem.jsx:84 Button flips to Remove
F4mediumAfter Reset App State, the product list still shows items as in the cart

Reset empties the cart and the badge clears, but every product button keeps saying Remove. Only the badge listens for cart changes; each button keeps its own copy, read once when the page loaded. The screen contradicts the cart until the user leaves the page and comes back.

Fix: Have product buttons read cart state from one shared source, or subscribe to cart changes like the badge does.

graph check · silent failure · Buttons still say Remove for an empty cart

  • components/InventoryListItem.jsx:22 Button state copied once on mount
  • components/CartButton.jsx:16-22 Only the badge registers a listener
  • utils/shopping-cart.js:64-72
F5mediumLogging back in forgets where you were

The redirect to login saves the page you were on, but login ignores it and always opens the product list. Anyone sent to log in from the cart or a product page has to find their way back. The model counts 2 actions from there to the goal.

graph check · progress loss · Log back in

  • components/PrivateRoute.jsx:16 state.from saved
  • pages/Login.jsx:58-59 Always history.push(ROUTES.INVENTORY)
F6mediumLogging out keeps the cart for the next person

The cart lives in the browser's localStorage, not with the account. Logout only removes the session cookie, so whoever logs in next on the same browser sees the previous person's cart.

Fix: Clear the cart on logout, or store it per user.

code review · Log out (cart kept)

  • components/DrawerMenu.jsx:142-146 removeCredentials() only
  • utils/shopping-cart.js:39-56 One global 'cart-contents' key
F7lowReset App State wipes the cart with no confirmation and no undo

One tap in the menu, next to Logout, clears everything.

code review · Reset App State empties cart

  • components/DrawerMenu.jsx:138-164 Logout and Reset sit next to each other
F8lowThe sort order resets every time you come back to the list

The list always starts sorted A to Z. Open a product and press Back, or tap Continue Shopping in the cart, and your chosen sort is gone.

Fix: Keep the sort in the URL or in storage.

code review · Product list

  • pages/Inventory.jsx:19-22 Initial state is A to Z on every mount
  • pages/InventoryItem.jsx:59-61 Back pushes a fresh list page
F9infoCart listeners are added on every mount and never removed

Each time a page with the cart badge mounts, it adds another listener, and none are removed. Over a session, every cart change re-runs listeners for badges that no longer exist.

code review · Save item to cart

  • components/CartButton.jsx:20-22 No cleanup function
  • utils/shopping-cart.js:74-79

How this was made

Static reading of the app's source at the commit above, covering login, the product list, product pages, the cart and the side menu. Later pages and the experimental catalog pages were not mapped.

Graph checks find dead ends, traps, loading states nothing resolves, ghost states, silent failures and loops that undo progress. A code review adds what the graph can't see. Severity drops a level for paths that only happen rarely.
